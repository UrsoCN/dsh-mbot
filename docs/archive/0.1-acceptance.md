## M0：DSH 行为实测

2026-11-25，Linux，DSH `0.2.2-rc.5`。本文件保留 M0 的历史验收；已完成事项汇总在 [0.1 发布说明](../../RELEASE_NOTE.md)，当前边界见 [设计](../../DESIGN.md)。

### 复现

依赖：`bash`、`git`、`jq`、`flock`、`timeout`、`zstd`、`node`、`dsh`。`zstd` 仅供此探针查看默认压缩的持久会话，框架运行时不增加该依赖。在仓库 `.env` 中配置 `DEEPSEEK_API_KEY`，或从环境提供，然后运行：

```bash
bash tests/m0-spike.sh all
```

可单独选择 `baseline`、`permissions`、`subagents`、`patch`、`interrupt`。`MBOT_DSH` 可指定 dsh 可执行文件，`MBOT_SPIKE_TIMEOUT` 可修改每个场景的秒数上限（默认 300）。这是调用真实 API 的验收探针，不是未来 M1/M2 的离线回归测试。

脚本创建 `/tmp/mbot-m0.XXXXXX` 下的 Git 工作区、独立 `DSH_HOME`、外置脚本、日志和缓存；不重设 HOME、不修改真实 DSH profile。以 `env -i` 启动 dsh，凭据只来自隔离 `$DSH_HOME/.env`，不出现在 argv 或终端输出。结束时删除该凭据副本；保留日志供复核。真正的越界测试使用当前仓库中的临时 `.m0-outside.XXXXXX/denied.txt`，退出时清理该目录。

日志包括每场景的 `.jsonl`、`.stderr`、`.metrics.json`，以及解压后的 `logs/sessions/*.jsonl`。不把原始会话日志提交进框架 Git 仓库。

### 本轮验收

完整运行的证据目录：`/tmp/mbot-m0.By95Ln/logs`（本机临时产物，清理后用上述命令重新生成）。5 个场景的进程退出码均为 0，`final.reason.kind` 均为 `completed`；探针断言失败数为 0。

| 场景 | 总耗时 | 实际证据 |
|---|---:|---|
| baseline | 7,168 ms | `pwd + ls -a` 成功；顶层答复带根 AGENTS 口令；7 类 NDJSON 事件 |
| permissions | 12,507 ms | 内部读写成功；外部脚本/PATH/运行标识/flock 正常；越界文件写拒绝，外部原文件不变 |
| subagents | 29,595 ms | 两 Worker 同时 running；各自继承环境与 AGENTS；孙代理受深度闸门拒绝；完成后恢复写文件 |
| patch | 3,959 ms | 持久 `assistant/message.data.message.source.model` 为 `deepseek-v4-pro` |
| interrupt | 12,024 ms | 启用 overlay 后，中断正在 `sleep 60` 的 Worker，实际状态转为 inactive |

这些耗时包含启动、网络、模型执行、工具及结束刷新；初次模型请求也可能命中其他调用留下的服务端缓存。它们不是纯进程启动计时，也不是多样本性能评测。

基线有两次 `step_end`，用量逐步相加：`inputTokens=572`、`outputTokens=178`、`cacheReadTokens=11648`、`cacheWriteTokens=0`、`totalTokens=12398`。这里 `inputTokens` 是未命中的输入部分，缓存读已包含在 `totalTokens` 中，不能再累加一次。该统计只覆盖顶层；Worker 完整步骤在各自的持久会话中。

### 实现时必须保留的差异

- `final` 只含 `{type, sessionId, reason, text}`，没有汇总 token。启动失败可只有 `error`，甚至没有 JSON 事件；M2 同时检查进程退出码和终止原因。
- 越界 `write` 的事件是 `status=error`、`error.code=FS_SANDBOX_DENIED`；越界 bash 命令的事件却仍是 `status=completed`，实际 shell 返回 1，输出 `Permission denied`。工具完成不代表业务成功。
- DSH 的临时区可写。第一轮把拒绝目标放在 `/tmp`，两类写入都成功；修正目标位置后才实测到拒绝。这是权限边界的一部分，不能把临时区中的外置脚本当成只读工具部署。
- fresh Worker 的 prompt 未包含根口令；其持久最终答复仍带口令，证明工作区 `AGENTS.md` 原生加载。派活仍需要 `botctl boot` 注入 SOUL、MEMORY 和任务。
- 默认 `maxDepth=1`、`maxActiveSubagents=8`。深度 2 的工具实际失败；并发仅实测两路，8 是安装包源码中的默认值。
- `send_message` 模型工具的实际结果是 `message delivered to agent probe-a`，不是设计初稿所说的 `messageId` 对象。恢复轮产出以实际文件和子会话为证。
- `interrupt_agent` 默认关闭。M4 传入 `tool-subagent-control.config.interrupt: true` overlay；实测返回 `interrupt requested for agent slow-probe`，随后 `list_agents` 显示 inactive。

默认模型是 `deepseek-official/deepseek-flash`。本次切换到 Pro，以响应源而非模型自述核实覆盖有效；Dreaming 要明确使用 Flash 时，同一入口传入以下 overlay：

```yaml
- id: agent-default-model
  config:
    provider: deepseek-official
    model: deepseek-flash
```

后续 M1 不依赖 DSH 的在线调用；M2 的 renderer/guard 和 M4 的控制 patch 应按这些实测结果实现。

## M2：单次运行闭环验收

2026-11-26，Linux，DSH `0.2.2-rc.5`。本文件保留 M2 的历史验收。入口和恢复操作见 [README](../../README.md#运行维护与恢复)，当前边界见 [设计](../../DESIGN.md#事务与上下文)。

### 复现

离线回归：

```bash
bash tests/run.sh
```

包含 M1 的 16 组集成检查和 M2 的 15 组运行检查。真实模型验收：

```bash
bash tests/real-run.sh
```

此命令使用仓库 `.env` 或启动环境中的 `DEEPSEEK_API_KEY`，将工作区、DSH_HOME、配置、缓存和运行临时文件放到 `/tmp`；不改 HOME 或用户 DSH profile，不创建凭据文件副本。真实验收产物保留供复核，离线成功用例自动清理。

### 真实结果

本轮工作区：`/tmp/mbot-real-run.VbVY33/ws`。run-id：`20261125T164053Z-run-d6f1`（UTC；本地日期 2026-11-26）。

- 请求：`在看板上加一个任务：整理 README`。
- Chief 实际执行 `botctl board add "整理 README" --owner coder`，创建 `001` 与 `tasks/001.md`，状态 todo。
- 共享 MEMORY 与启动前逐字一致，guard 违规列表为空，botctl lint 通过。
- 数据仓库有 `human: init` 和一个 `run(chief): …` 提交；HEAD 父节点保持原初始化提交，工作树干净。
- transcript 记录实际工具调用、结果和最终回答；meta 标记 `success=true`、退出码 0、reason completed。
- DSH 调用耗时 24,464 ms；顶层用量：输入未命中 3,070、输出 1,210、缓存读 38,400、总 token 42,680。该样本不是延迟承诺，缓存不重复计入总量，Worker 的完整成本不在此统计中。

原始流与 stderr 在工作区 `.mbot/runs/`，Markdown 与 meta 在 `transcripts/2026-11-26/`。路径是临时证据位置，清理后按复现命令重新生成。

### 回归与恢复证据

| 场景 | 验收行为 |
|---|---|
| 正常建任务 | 一次调用一个干净提交，usage 只计算顶层 step_end |
| 改共享/私有 MEMORY、SOUL、AGENTS、wiki、其他文件 | 恢复越权项，记录违规，保留合法任务，运行判失败 |
| 删除 inbox 原始内容 | 按字节前缀发现非追加，恢复候选文件 |
| 改坏 BOARD | 恢复看板与本次任务修改，避免孤立任务 |
| 伪造旧 transcript、旧 raw、失败计数和忽略文件 | 恢复历史内容与控制状态，清理新越权文件 |
| 把 tasks 或 PAUSED 改成软链 | 修复工作区路径，外部目标内容不变 |
| Agent 自行提交、移动 HEAD | 记录观察 HEAD，恢复原提交父节点并立即 PAUSED |
| 运行内调用 mbot | 嵌套调用被拒，普通工具结果仍能结束父会话 |
| 请求/最终回答/stderr 含密钥 | 入库记录、commit 摘要、终端输出脱敏；原始日志保留原样 |
| 非法 JSON、缺失或错误 final、退出 1 | 保存失败审计、累计失败；三次连续失败自动暂停 |
| 超时 | 限时结束，meta 记录退出 124，保存 transcript 并计失败 |
| 并发 run 和人类 botctl 修改 | 第二个 run 跳过，人类变更报忙；期间人工 pause 保留 |
| 脏工作树 | 模型启动前拒绝，不创建业务改动 |
| Git 元数据不可用 | 原始证据保留、失败计数 +1、PAUSED；不伪造成功或强行提交 |

恢复时先查看 `mbot status` 和失败记录。普通运行失败可在处理问题后 `mbot resume`；HEAD/控制路径异常、Git 元数据损坏或提交失败，需要先检查并修复保留的工作区。resume 会清除 PAUSED 与连续失败计数，不会自动丢弃未提交改动。

## M3：Dreaming 与记忆闭环验收

2026-11-26，Linux，DSH `0.2.2-rc.5`。本文件保留 M3 的历史验收。入口见 [README](../../README.md#dreaming调度与运维)，当前边界见 [设计](../../DESIGN.md#事务与上下文)。

### 复现

```bash
bash tests/run.sh
bash tests/real-dream.sh
```

第一条命令不调用模型：16 组基础、15 组运行、11 组 Dreaming 检查，共 42 组。第二条使用仓库 `.env` 或环境中的 DeepSeek key，创建 `/tmp` 下独立数据仓库、DSH_HOME、配置和缓存；不改 HOME/用户 DSH profile，不创建凭据副本。成功离线数据清理，真实数据保留供复核。

### 真实闭环

本轮工作区：`/tmp/mbot-real-dream.bPP67Q/ws`。

| 步骤 | 实际结果 |
|---|---|
| `mbot run chief "以后周报一律用中文，记住这条"` | remember 投递到 inbox，MEMORY 与初始内容逐字相同，无新任务 |
| `mbot dream` | 共享 MEMORY 新增用户偏好；来源是 inbox，added 使用本地 2026-11-26；报告与 checkpoint 同一个 dream commit |
| 英文请求 `Draft a short weekly report with three sections: Completed, Next, Risks.` | 回复中文周报正文；空看板下用草稿并说明没有已登记事实，没有编造进展 |
| `git revert <dream commit>` | 恢复初始 MEMORY，移除该报告和 checkpoint；lint 通过，工作树干净 |

Dream commit：`ad1f0bb`；run-id：`20261125T171408Z-dream-ceb9`。这是 UTC 时间，added 日期按本地日期设置。报告和 metadata 在 revert 后可从 Git 中查看：

```bash
git -C /tmp/mbot-real-dream.bPP67Q/ws show ad1f0bb:dream-reports/20261125T171408Z-dream-ceb9.md
git -C /tmp/mbot-real-dream.bPP67Q/ws show ad1f0bb:dream-reports/20261125T171408Z-dream-ceb9.meta.json
```

本次选入 8,009 字节：inbox 142 字节、transcript 7,867 字节，低于 64,000 字节预算，pending 为空。Dreaming 调用 20,771 ms；顶层 token：输入未命中 5,737、输出 2,060、缓存读 75,776、总量 83,573。缓存不重复计入总量；这是单次样本，非固定延迟或整棵代理树的成本承诺。

### 离线证据

- 同一成功事务写共享/私有 MEMORY 与 wiki，原始候选保持不变；后续 run 的冷启动能读取规则，revert 后规则不再注入。
- 共享/私有预算超限、wiki 超限、链接失效、模型出错、报告缺失、报告路径错误、依据为空或写错文件，都恢复所有记忆，只提交失败报告/metadata。
- 旧行删除必须逐文件说明；MEMORY.md 的依据不能被 bots/coder/MEMORY.md 的条目冒充。普通 wiki 页面可在有效依据下删除，必需的 wiki/_index 保留。
- Dreaming 偷改 BOARD 或新建任务被恢复；run/dream 共用锁和嵌套防护。
- 48 字节的 UTF-8 完整行批次能跨多次 dream 续读；未读片段期间追加新内容，按偏移顺序处理，每个输入字节只消费一次。完成后不重复处理旧输入。
- 失败不推进 checkpoint；被替换的未读源使用当前版本，被重命名的源重新入队，避免因 Git rename 分类漏读。
- 完整单行装不进预算时保留进度、生成失败报告且不调用模型，提高预算后可继续。
- 模型报告与 metadata 脱敏；子命令 `--help` 只显示帮助，不再进入候选；本地日期与 UTC run-id 区分。

Checkpoint 存在成功报告 metadata 中，与记忆同一个 commit。失败 metadata 的 processed 表示本次选入材料，失败后不视为已处理；重试仍使用上一成功 checkpoint。revert 也回滚进度，后续会重新整理仍存在的候选。

M3 复用了 M2 生命周期，框架 `bin/` + `lib/` 当前 975 行（含注释和空行）。设计中的体积目标由 800 调整为 1200，以保留显式的续读和失败恢复；纯 Bash、Markdown + Git、单阶段 Dreaming、无插件/数据库的框架不变。

## M4：星型调度验收

2026-11-26，Linux，DSH `0.2.2-rc.5`。本文件保留 M4 的历史验收。入口见 [README](../../README.md#dreaming调度与运维)，当前约定见 [设计](../../DESIGN.md#身份与数据模型)。

### 复现

```bash
bash tests/run.sh
bash tests/real-schedule.sh
```

离线有 16 + 15 + 11 + 8 = 50 组检查，不调用模型。真实测试使用仓库 `.env` 或环境中的 DeepSeek key，创建独立 `/tmp` 工作区、项目、DSH_HOME 和缓存；不改 HOME 或用户 DSH profile。zstd 仅用于解压持久会话验证 Worker 第一条工具命令，不增加框架运行依赖。

### 真实结果

工作区：`/tmp/mbot-real-schedule.sH10dB/ws`；外部项目：同目录旁的 `project`。

| 阶段 | 结果 |
|---|---|
| 并行开发 | Chief 建 001/002，持久写派活说明并标 doing；coder-001/002 同时 running |
| Worker 001 | 第一工具操作 boot coder --task 001；写 greet.sh，默认输出 Hello, world!，Ada 输出 Hello, Ada!，参数不 eval；结果写自己任务单 |
| Worker 002 | 第一工具操作 boot coder --task 002；独立写中文 README，用法与输出正确，结果写自己任务单 |
| Chief 验收 | 只读验收两份产物，验证输出、文件和 coder 结果；两个任务 done；外部项目 HEAD 未变 |
| 人为卡住 | 新任务 003，coder-003 boot 后写 started 标记并 sleep 30；Chief 确认进入 sleep，再 interrupt_agent |
| 中断结果 | coder-003 inactive；003 blocked，附「人为中断验收，Worker 未完成」原因；不误标 done |
| 归档 | 001/002 原样移动到 tasks/archive/2026-11，003 保留；chore(archive) 提交；MEMORY 与初始内容逐字相同，lint 通过，数据仓库干净 |

真实 list_agents 的原始结果：

```text
lead [running] — root agent
coder-001 [running] — 实现 greet.sh 脚本
coder-002 [running] — 编写 README.md 中文说明
```

两次 run 的 metadata 均为 `success=true`、退出 0、reason completed、violations 空；grants 明确记录项目物理目录。持久会话共三个 Worker，脚本从各自日志验证了第一条工具调用为对应 boot。数据仓库提交为：

```text
26e1589 chore(archive): archive 2 done tasks
5ff99ef run(chief): 20261126T004457Z-run-2cf3 …
ba58098 run(chief): 20261126T004328Z-run-7a08 …
8753682 human: init
```

并行 run 调用 89,167 ms，顶层总 token 232,345（缓存读 208,768）；中断 run 调用 30,965 ms，顶层总 token 109,626（缓存读 100,992）。这些只覆盖 Chief 的顶层流，不是含 Worker 的总成本，也不是延迟承诺。

### 离线边界

- 无 todo/doing 的 tick 即使 DSH 不可用也直接跳过；有 doing 时优先，否则按看板顺序选择 todo，blocked 不变。
- archive 保留 done 任务字节，其他状态保留；无完成项不提交，不调用模型；归档后的 ID 不复用。
- 目的文件冲突、提交失败会恢复看板/任务与索引，不留下半份归档。
- grants 支持空格和共同前缀，逐项形成独立 add-dir；拒绝 root、保护目录重叠、空项、重复、相对路径、软链别名与非规范路径，均在调用模型前失败。
- dream 不授予外部目录；tick/archive 尊重 PAUSED、全局锁和运行内禁用规则。
- 历史归档任务不检查旧链接目标，原始记录不因移动而改写。

本次模拟项目位于 `/tmp`，该区域在本机 DSH 中本就可写；这里验证了真实参数接受、目录记录及任务行为，不把 `/tmp` 的写成功当成非临时目录沙箱隔离的证明。每个 Worker 的文件范围由任务协议限定，仓库级边界由 DSH grants 限定；外部产物由人类审阅、提交和合并。

| cron-run tick | 固定工作区，执行 tick，空闲/锁忙/PAUSED 如实记录 |
| cron-run nightly | archive 成功后接 dream，归档错误阻止模型调用 |
| 可选 push | 默认关闭；成功 dream 本地提交后推既有 upstream；无 upstream、URL 改变、拒绝或超时保留本地成功 |
| recover | `/tmp` clone → lint → 只读冷启动；本次清空 grants/关闭 push；校验成功 transcript、零违规与数据未变 |
| observe | 人工加锁、脱敏并提交 ops-log；保存首次 UTC、当日状态、预算、lint、最近 dream 与留存审计违规数量 |

cron 日志保存在 `${XDG_STATE_HOME:-$HOME/.local/state}/mbot/logs`，权限 600，每次独立文件。目录不得在工作区、框架或 DSH_HOME 内。push 的 `.push.log/.push.json` 在 `.mbot/runs` 忽略目录；日志脱敏已知 secret 和 HTTP URL userinfo，push 不提示输入凭据。超时后最多额外等 5 秒强制结束。

observe 不替代人工核对。lint 错误会入记录并返回非 0；运维文件预算超限或目标有未提交改动则恢复/拒绝。违规计数来自当前留存 metadata，不自动判断是否处理；revert 删除的报告仍须从 Git 历史核对。`wiki/ops-log.md` 是所有 Bot（包括 dream）的只读文件，不能让模型编造观察结论。

### 结构与行为

| 资源 | 作用 |
|---|---|
| package.json | dsh.bundle、版本/平台、peer 共享、公开 ESM/.d.ts 与 mbot/botctl bin |
| cordis.patch.yml | 插入 mbot、tool-mbot、command-mbot 三行 |
| plugin/index.js | Cordis mbot 服务与 volatile Config；通过 DSH subprocess provider 启动固定脚本 |
| plugin/tools.js | 原生 botctl；结构化任务/候选操作；sandboxPolicy 与 approveEscalation |
| plugin/commands.js | 人类 /mbot 控制命令；命令不送模型，不按 shell 解析 |
| templates/workspace/gitignore | init 生成 .gitignore，避免 npm 省略模板 dotfile |
| lib/bin/prompts/patches/ops | 原有事务、调度、报告、护栏与运维实现，完整入包 |

原生工具的所有操作需要 danger-full-access 或一次 DSH 审批，因为修改的是宿主配置的数据仓库；拒绝发生在执行脚本之前。模型不能选择任意目录，不能调用 run/dream、直接写 MEMORY 或修改长期规则。受 mbot 管理的运行继续用 Bash botctl，由现有宿主护栏验收；原生工具和人类命令拒绝运行内绕过。

服务每次捕获 workspace，argv 不经过 shell；传递 AbortSignal，返回脱敏输出，卸载时终止并等待自己的子进程。原生工具/人类命令注册由 Cordis effect 释放。卸载 bundle 后数据仓库保留，服务和入口不再可用。
